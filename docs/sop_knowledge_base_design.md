# SOP 知识库设计

## 设计原则

三层映射：Excel SOP Review Checklist（检查点骨架）→ 标准底稿位置（在哪查）→ MD SOP 易错点（怎么判）

## 检查点映射表（12条可LLM判断）

以下是从26检查点中筛选出的**规则引擎无法判断、需要LLM做定性分析**的条目。

### 检查点 1: PSP执行完整性

| 维度 | 内容 |
|------|------|
| **Excel SOP来源** | `Review checklist` 序号1: "底稿应执行PSP均得到执行，拒绝执行理由恰当、充分" |
| **MD SOP来源** | §汇总·第一步: 基础操作 §1-2 + 易错点 §1-5 |
| **标准底稿位置** | 汇总 sheet: F列(程序页), G列(是否执行), H列(不执行原因) |
| **案例数据** | 汇总!G12="否", H12="本期无复核法律费用" |
| **规则引擎做了** | 判空(执行/原因是否为空) |
| **LLM需要判断** | H列的拒绝理由是否"恰当、充分"——与BKD实际内容是否矛盾 |
| **判断标准(MD SOP)** | 易错点#1: 错误拒绝PSP；#4: 各底稿页实际执行的程序与程序要求不一致；#5: 拒绝PSP未解释原因或解释不具体 |

### 检查点 2: 预期建立充分性

| 维度 | 内容 |
|------|------|
| **Excel SOP来源** | `Review checklist` 序号1: "未建立预期或未恰当建立预期" |
| **MD SOP来源** | §VC/VD BKD·第二步: 设定预期 + 易错点 |
| **标准底稿位置** | VC.00/VD.00 BKD: 第17-21行(预期描述区域) |
| **案例数据** | VC BKD 第18-20行有预期文字；VD BKD 第17-19行有预期文字 |
| **规则引擎做了** | 判空 |
| **LLM需要判断** | 预期是否"恰当"——是否仅写结论未写依据 |
| **判断标准(MD SOP)** | 易错点#1: 未记录波动预期；#2: 仅记录预期结果未记录依据和理由；#3: 记录的波动预期与实际情况差异较大 |

### 检查点 3: ARP分析充分性

| 维度 | 内容 |
|------|------|
| **Excel SOP来源** | `Review checklist` 序号1: "已对超过门槛、性质异常或与预期不符的变动进行调查，并对就原因执行的调查结果详细记录，分析合理" |
| **MD SOP来源** | §VC/VD BKD·第四步: ARP分析 + 易错点 |
| **标准底稿位置** | VC.00/VD.00 BKD: O列(Notes索引), P列(定量标记), Q列(定性标记), 下方Notes区域 |
| **案例数据** | 需读取P/Q=是的行的Notes内容 |
| **规则引擎做了** | 检查P/Q=是时O列是否为空 |
| **LLM需要判断** | Notes内容是否"分析合理"——是否仅描述变动金额未解释原因 |
| **判断标准(MD SOP)** | 易错点: ①仅描述变动金额与比例未分析原因；②ARP分析为未审数而非审定数；③仅描述未解释变动；④仅解释费用性质不解释变动；⑤特殊费用(诉讼费/罚款/律师费)未做分析；⑥仅分析未说明程序及索引 |

### 检查点 4: 特殊费用关注（法律/诉讼/中介）

| 维度 | 内容 |
|------|------|
| **Excel SOP来源** | `Review checklist` 序号2: "费用列报正确"，序号1: "底稿中索引至其他底稿的审计程序记录正确" |
| **MD SOP来源** | §VD BKD·第三步进阶: 关注性质特殊或异常项 §5(法律诉讼等中介机构费用) + §VD.01.3全文 |
| **标准底稿位置** | VD.00 BKD: D列(科目名称)；VD.01.3: 表1 |
| **案例数据** | VD BKD存在: 咨询费175,909、法律服务费173,180、中介服务费350,000、诉讼费160,000 |
| **规则引擎做了** | 关键词匹配列出特殊费用 |
| **LLM需要判断** | ①这些费用的性质是否触发VD.01.3法律费用复核；②汇总页拒绝执行法律费用复核的理由是否成立；③诉讼费是否已单独关注 |
| **判断标准(MD SOP)** | 管理费用中核算了咨询/法律/中介费用时需进一步筛选JE摘要检查是否含诉讼费；性质特殊的法律费用(诉讼费)需全部检查；未对性质特殊的法律费予以关注是易错点 |

## LLM System Prompt 设计

不是12条独立prompt，而是**一个统一的SOP-aware system prompt**，LLM加载一次即可处理所有检查点：

```
你是EY费用底稿AI审核助手。你已加载以下SOP知识库：

【SOP知识库】
（结构化的12条检查点 × 判断标准，约3000字）

【你的任务】
用户会传入底稿的结构化数据，并指定需要你判断的检查点。
你必须严格依据SOP知识库中的判断标准进行判断。

【判断规则】
1. 每个结论必须引用具体的SOP条款
2. 没有充分证据时返回 should_raise_note=false
3. 不得编造文件名、Sheet、行号或金额
4. 风险等级: High(违反SOP明确要求)/Medium(SOP建议但非强制)/Low(细微改进建议)
5. 只返回JSON，不要Markdown

【输入格式】
{检查点ID列表, 底稿数据JSON}

【输出格式】
{items: [{checkpoint_id, should_raise_note, risk_level, issue_type, reason(sop引用), suggested_action, confidence}]}
```

---

## 实现步骤

1. **构建 SOP 知识库 JSON**（一次性）：将上表 12 条检查点结构化为 LLM-readable 的 JSON
2. **数据提取层**：针对每条检查点，从底稿中提取需要的结构化数据
3. **LLM 调用**：一次调用传入多个检查点 + 对应数据，批量判断
4. **结果格式化**：LLM 输出统一转为 ReviewNote 格式

## 与规则引擎的分工

| 检查内容 | 谁做 |
|---------|------|
| 单元格为空 → High | 规则引擎 |
| P=是且O为空 → High | 规则引擎 |
| KI全部为0 → High | 规则引擎 |
| 负值"是否抽样"为空 → High | 规则引擎 |
| C7填CNY/C8填IFRS → High | 规则引擎 |
| BKD货币显示IFRS → High | 规则引擎 |
| 缺失标准Sheet → High/Medium | 规则引擎 |
| PSP拒绝但原因不足 → ??? | **LLM 补充判断** |
| ARP写了但写得不充分 → ??? | **LLM 补充判断** |
| 剔除项X-ref是否合理 → ??? | **LLM 补充判断** |
