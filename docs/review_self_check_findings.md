## 对 32 项发现的准确性判断

### 基本准确，建议补规则

- #1 C7/C8 填反。
- #2 分析日期等于期末。
- #4 法律费用程序拒绝理由与 BKD 线索冲突。
- #6/#12 BKD 货币/单位显示 IFRS。
- #14 咨询费、中介服务费等特殊费用未做 Notes 或 ARP 分析。
- #18 长期待摊费用摊销缺少 X-ref。
- #24 TOD 样本总体包含制造费用/研发支出。
- #25 关键项 KI 数量和金额为 0。
- #26 负值分析未完成。
- #29 抽样工具输出页为空。
- #30 X-ref 填写模糊。

### 需要改口径

- #5 不宜表述为“标记矛盾”，更准确应为：执行 SAP 但未补充具体底稿索引或程序页引用不完整。
- #10/#19 不宜表述为“预期未记录”，因为底稿已记录一句预期；更准确应为：仅记录预期结果，未记录依据或具体理由。
- #20 “文本被截断”不应作为审计问题。单元格实际内容存在，更适合改为：截止性测试样本策略说明是否充分。
- #31 如果 TOD 是独立底稿一并上传，则不应直接判定主底稿缺少 TOD sheet 为 High。更准确应为：主底稿汇总页应有清晰 X-ref 指向独立 TOD 底稿。

### 可能存在误判

- #7/#13 “上期审定数显示为极小比例值”目前看可能误判。源数据中上期审定数列为金额，极小比例值更像是结构比列。
- #22 “样本量未区分 Key item 和代表性样本”方向可疑，但需要结合抽样工具结果和是否存在大于 TE/TT 的交易，不能仅凭样本数量直接定性。

## 当前规则主要误判

### 1. TB/BKD 科目余额表误报较多

当前规则按科目名称精确匹配，导致父级科目、明细层级科目被大量报为“未在 BKD 列示”。这不够准确。

建议优化：

- 使用科目编码前缀和叶子科目层级判断。
- 父级汇总科目不直接报 Medium。
- 匹配 BKD 的合并列示口径，而不是只做同名精确匹配。

### 2. 序时账关键词命中过宽

当前规则命中“咨询、调整、暂估”等关键词后直接出 Review Note，导致部分银行存款、其他应收款、在建工程暂估、汇兑损益行也进入结果。

建议优化：

- 先过滤科目全名是否属于销售费用或管理费用。
- 或按凭证号聚合，确认同一凭证中是否存在费用类分录。
- 对非费用类科目只作为候选证据，不直接形成审计 Review Note。

### 3. TOD 样本池被误判为测试结论不足

当前规则把“总样本池 / 剔除后样本池”也当成测试结论页检查，因此输出“TOD 测试结论线索不足”。样本池本身不一定需要测试结论，该判断不严谨。

建议优化：

- 样本池只检查总体范围、科目范围、金额和是否为空。
- 测试结论只在 TOD 主测试页、样本测试页或 Skywind 输出页中检查。

### 4. LLM API 失败不应进入审计 Review Notes

当前 DeepSeek 超时或 JSON 解析失败会进入 Review Notes。该信息属于系统运行状态，不属于审计发现。

建议优化：

- 从 Review Notes 中移除 LLM API 失败项。
- 在 HTML 页面或报告顶部显示 LLM 状态。
- 规则结果仍正常输出。

## 下一步优先级

### P0：先降误报

1. 修正 TB/BKD 匹配逻辑，避免父级科目和层级差异造成误报。
2. 修正序时账范围过滤，只对销售费用、管理费用相关候选形成 Review Note。
3. 修正 TOD 样本池误判，样本池不再检查测试结论。
4. 将 LLM API 失败移出 Review Notes。

### P1：补 High 风险漏报

1. TOD 样本总体包含制造费用/研发支出。
2. KI 数量和金额全为 0。
3. 负值分析未完成。
4. 主底稿与独立 TOD 底稿 X-ref 不清晰。
5. 法律费用程序与咨询费、中介服务费、诉讼费等线索冲突增强。

### P2：补 Medium 风险规则

1. BKD 预期依据不足。
2. ARP 波动说明不充分。
3. 异常波动但 P/Q 均为否。
4. 抽样工具输出为空。
5. Cut-off 样本策略与 TE/TT 关系检查。

## 总体结论

当前 MVP 已能演示上传、识别、输出 Review Notes 和标注版底稿，但质检准确度还不够。最急的不是继续增加发现数量，而是先降低误报，再补 TOD 和 BKD 分析充分性规则。否则现场展示时容易被质疑“有些问题不像审计发现”。
